# Table filters, pagination, and a quieter Claude label

Four changes to the frontend shell: the chat header lost its explainer, the Claude state moved from
the app header down to the chat composer, `GET /invoices` is now consumed page by page, and the
table grew a filter toolbar. Nothing new was added to `package.json`; motion stays CSS-only on
`--ease-out` under 300 ms, and every control keeps a 44 px target.

## What changed

| Before | After |
| --- | --- |
| "Ask about the invoices" plus a paragraph about LangChain writing the SQL | "Chat with our Agent", no paragraph |
| Empty thread read "No questions yet. Pick a suggestion above or type your own." | "Pick a suggestion or ask your own question." |
| Header chip: `● Postgres \| Claude: ready (claude-sonnet-5)` | Header chip: `● Postgres`. The model sits above the composer as `● claude-sonnet-5` |
| `GET /invoices` returned every row; the client sorted them | `GET /invoices?page=…&page_size=…&…` returns `{items, total, page, page_size}`; the server sorts |
| No search, no filters | Search, Status, Source, Sort, "Needs review", "Clear filters" |
| Count line: "32 invoices" | "32 invoices", or "8 of 32 invoices" when filtered |
| No pager | "1-25 of 32", Rows 10/25/50, Previous / Next |

## The query hook

`useInvoiceQuery` owns search text, the four filters, sort, page and page size, and runs the fetch
that follows them. One committed query object drives one effect, so a change produces exactly one
request, and an `AbortController` cancels the one it replaces.

- Typing commits after 250 ms of quiet, and the commit carries `page: 1` with it, so the debounce
  never fires a wasted request for the old page.
- Every non-search filter and every sort change commits immediately, also with `page: 1`.
- `baseTotal` remembers the total from the most recent unfiltered fetch, which is what lets the
  count line read "8 of 32 invoices". It only refreshes on an unfiltered fetch, so adding an invoice
  while a filter is on leaves the "of 32" one behind until the filters clear.
- `refreshAfterSave` is what the drawer's `onSaved` calls: it refetches, and when the sort is still
  Newest it jumps to page 1, where a just-saved row lands.

## States

| State | Behaviour |
| --- | --- |
| First load | Six shimmer rows, count reads "Loading…" |
| Page or filter in flight, rows already on screen | Previous rows stay, `.table-wrap--stale` fades them to 0.55 opacity over 180 ms, `aria-busy` is set. No layout jump, no collapse |
| Error | Unchanged: "Could not load invoices" plus "Try again", which refetches the current page |
| Empty, no filters | Unchanged: "No invoices yet" |
| Empty, filters active | "No invoices match these filters." plus a "Clear filters" button |

## Accessibility

- Every filter has a visible `<label>` bound with `htmlFor`: Search, Status, Source, Sort, Rows. The
  clear glyph inside the search field is a button with `aria-label="Clear search"`, sized to the
  full 44 px height of the input.
- The filter row is a `role="group"` labelled "Search and filter invoices".
- The pager range is `aria-live="polite"` and carries a visually hidden ", page 1 of 2" after the
  visible "1-25 of 32", so the position is announced, not just the row span.
- Previous / Next are `disabled` at the ends rather than hidden, and inherit the 44 px `.btn` height.
- "Needs review" is a real checkbox inside a pill; the box stays visible so focus lands somewhere
  obvious, and the pill tints to the accent when checked. State is carried by the label text, not by
  colour alone.
- The composer label is text plus a decorative dot (`aria-hidden`), prefixed by a visually hidden
  "Model", with `title="Answers are generated by Claude Sonnet through LangChain"`. Muted
  `#9aa4b4` on `--surface` is about 6.7:1.
- Inputs are 44 px tall; the toolbar is one row at desktop and wraps to two under 900 px, where the
  search field takes the full first row.

## Notes and trade-offs

- **`seed-fallback` is not offered in the Source select.** The API accepts it, but the UI lists only
  seed / extracted / uploaded / imported, and the UI value "seed" maps straight to `source=seed`.
  Rows stored as `seed-fallback` (a seeded row whose extraction fell back) are therefore invisible
  while "seed" is selected. The live database currently holds 0 of them, so nothing is hidden today.
- **The header dot now tracks the API, not the key.** It is green when `/health` reports `ok`, red
  when the API is unreachable. The key state was the only reason it used to go amber, and that state
  now lives on the composer.
- Search matches vendor, invoice number, email and PO number server-side; the placeholder names the
  first three to stay short.
- Sorting is entirely server-side now, so the old client-side `byDateDesc` is gone and the table
  caption no longer claims "newest first".
